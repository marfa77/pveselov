# Ep 04 — Change the work, not the slide
slug: change-the-work-not-the-slide

## Spoken

Hi, Pavel here. Building AI in the Enterprise — for IT directors who are tired of slides that never touch Monday morning.

You picked a few domains. Good. Now the hard part: change the work, not the slide. Phase three in the playbook. Rebuild whole workflows around AI instead of bolting a model onto old steps. Bain's clients have a phrase for the wrong version: paving the goat trails. Faster goats. Same trail.

Start with the people who do the work. Redesign each chosen workflow from a clean sheet with them. Remove steps. Do not only speed them up. Done when the new workflow has fewer hand-offs and a non-AI baseline you can compare against. In Harvard Business Review's manufacturer case, early quotes went from hours of engineering time to a short estimate by non-designers, and win rate moved in months — because the work changed, not only the tool.

Next: capture judgment, not documentation. Run moderated panels of experienced practitioners through real edge cases. Where they agree, write a rule. Where they disagree, record the reasoning as context for whatever system you build. Done when your context files hold escalation thresholds, exceptions, and tone — reviewed by the experts themselves. Every company can buy the same models. The difference is written-down judgment. HBR tells the ITA Group story: the first months of codifying expertise were slow, then software timelines shrank from months to weeks.

Keep the architecture simple. Start with one model call plus retrieval and examples. Move to a scripted workflow. Only then to an autonomous agent — when the simpler step measurably fails. Done when every agent in production has a written reason why a workflow was not enough. Anthropic's engineers, writing about building effective agents, found the strongest implementations used simple composable patterns, and warned that the right answer might mean not building agentic systems at all.

Invest in tools more than prompts. Document every tool an agent uses the way you would for a junior developer. Test how the model actually calls it. Done when tool definitions have examples, edge cases, and clear boundaries — and failures get fixed in the interface, not only in the prompt. Anthropic spent more time on tools than on the prompt when building their coding agent; something as plain as absolute file paths changed behaviour sharply.

Budget for people, not just models. Plan effort roughly ten percent algorithms, twenty percent technology and data, seventy percent people, organisation, and process change. That is BCG's ten-twenty-seventy rule. Done when the AI budget has explicit lines for training, change, and workflow redesign. If seventy percent of the effort is organisational, an AI team staffed only with engineers is set up to stall.

In the room this week, resist the demo that only shows a happy path. Ask: who redesigned the steps. Where did judgment get written down. Why is this an agent and not a workflow. Where is the people line in the budget.

This week.

Take one domain from episode three. Map the current workflow on one page with someone who lives it.

Mark steps to remove, not only to accelerate.

Schedule one judgment panel — ninety minutes, real edge cases, write rules and disagreements.

Write a one-line architecture choice: model call, workflow, or agent — and why.
